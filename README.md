# YAML Bookmarks

A simple, personal bookmark manager. Every bookmark is one YAML file under
`$HOME/.yaml-bookmarks/`, named after a filesystem-safe escaping of its URL.
Comes with a CLI and a localhost-only web UI that installs as a PWA.

It's meant to be run by one person on their own machine. Bookmarks are **not**
served over the network, so there is no login or authentication.

## Install

```bash
pip install -e .
```

This installs the `yaml-bookmarks` command and pulls in PyYAML and Flask.

## CLI

```bash
yaml-bookmarks add https://example.com -t "Example" -d "A description" --tags "web,reference"
yaml-bookmarks add https://example.com -f work/ideas          # file it under a folder
yaml-bookmarks update https://example.com -f work/ideas -t "New title"  # only changes fields you pass
yaml-bookmarks list                                           # one line each
yaml-bookmarks list -v                                        # with description, tags, folder, dates
yaml-bookmarks list -f work/ideas                             # only that folder
yaml-bookmarks list --tag web                                 # filter by tag
yaml-bookmarks remove https://example.com -f work/ideas       # alias: rm
```

Folders / collections:

```bash
yaml-bookmarks folders                                        # show the folder tree with counts
yaml-bookmarks mkdir personal/finance                         # create an (empty) folder
yaml-bookmarks move https://example.com --from work/ideas --to reading/tech   # alias: mv
```

Point at a different directory with `--dir PATH` or the `YAML_BOOKMARKS_DIR`
environment variable.

## Folders

Bookmarks can be organised into folders and subfolders, and those folders **are
real directories** under `$HOME/.yaml-bookmarks/`. A bookmark in `work/projects`
is simply the file `~/.yaml-bookmarks/work/projects/<escaped-url>.yaml`. The
filesystem is the single source of truth, so the folder is derived from the
file's location and is *not* duplicated inside the YAML. Move a file with your
OS file manager and the app follows along; the same URL may live in more than
one folder.

## Encryption

Any bookmark can be encrypted with a password. Encrypted bookmarks are stored as
opaque `<uuid>.yaml` files (the URL never appears in the name or in cleartext),
and they are **invisible until you unlock with the password** — so someone who
finds the files can't read them, and the app won't even list them. See
[docs/encryption.md](docs/encryption.md) for the full design.

```bash
yaml-bookmarks add https://secret.example -e -p mypassword     # store encrypted (🔒)
yaml-bookmarks list                                            # encrypted ones are hidden
yaml-bookmarks list -p mypassword                              # unlock to see them (marked 🔒)
```

- Encryption uses AES-256-GCM with a key derived from your password via scrypt;
  the whole record is encrypted, a per-vault salt is embedded in each file, and
  each file is self-contained — copy any subset to another machine and unlock
  with the same password.
- In the web UI, a **padlock** in the header toggles it: click to enter a
  password (revealing encrypted bookmarks and encrypting new ones), click again
  to lock and hide them. Only one password is active at a time.

## Web UI

```bash
yaml-bookmarks web            # opens http://127.0.0.1:22222 in your browser
yaml-bookmarks web --port 9000 --no-browser
```

- Bound to `127.0.0.1` only, and requests with a non-local `Host` header are
  rejected (guards against DNS-rebinding).
- **Three-pane layout**: a collections sidebar on the left (folder tree with
  counts, collapsible, "New collection" button), the bookmark list in the
  centre, and the add/edit form on the right. On narrow screens it collapses to
  a single column with the form on top. Editing a bookmark and changing its
  collection moves it; the ⬇ Fetch button fills in title/description/keywords
  from the page.
- **Installable as a PWA**: because `http://localhost` is a secure context, your
  browser will offer to install it. It ships a web manifest, a service worker
  (so the shell launches offline), and app icons — all generated by the server,
  no binary assets in the repo.

## How URLs become file names

`escape_url` keeps lowercase letters, digits, `-` and `.` as-is and rewrites
everything else — including uppercase letters — as `_XX` (hex of each UTF-8
byte). Uppercase is escaped so `Foo` and `foo` don't collide on case-insensitive
Windows/macOS file systems. The mapping is deterministic (so add/update/remove
always find the same file) and reversible. Very long URLs are truncated with a
short hash appended; the full URL is always stored inside the file too.

Example: `https://example.com/Path` →
`https_3A_2F_2Fexample.com_2F_50ath.yaml`

## A stored bookmark

```yaml
url: https://example.com
title: Example
description: A description
tags:
- web
- reference
created_at: '2026-07-25T20:41:28+00:00'
updated_at: '2026-07-25T20:41:28+00:00'
```
