# YAML Bookmarks

A simple, personal bookmark manager. Every bookmark is one flat
`$HOME/.yaml-bookmarks/bookmarks/<uuid>.yaml` file; its folder is a `path` field
*inside* the file, not a directory on disk. Comes with a CLI and a
localhost-only web UI that installs as a PWA.

It's meant to be run by one person on their own machine. Bookmarks are **not**
served over the network, so there is no login or authentication.

## Install

```bash
pip install -e .
```

This installs the `yaml-bookmarks` command and pulls in PyYAML and Flask.

## CLI

```bash
yaml-bookmarks add https://example.com -t "Example" -d "A description" --tags "web,reference"
yaml-bookmarks add https://example.com -f work/ideas          # file it under a folder
yaml-bookmarks update https://example.com -f work/ideas -t "New title"  # only changes fields you pass
yaml-bookmarks list                                           # one line each
yaml-bookmarks list -v                                        # with description, tags, folder, dates
yaml-bookmarks list -f work/ideas                             # only that folder
yaml-bookmarks list --tag web                                 # filter by tag
yaml-bookmarks remove https://example.com -f work/ideas       # alias: rm
```

Folders / collections:

```bash
yaml-bookmarks folders                                        # show the folder tree with counts
yaml-bookmarks mkdir personal/finance                         # create an (empty) folder
yaml-bookmarks move https://example.com --from work/ideas --to reading/tech   # alias: mv
```

Point at a different directory with `--dir PATH` or the `YAML_BOOKMARKS_DIR`
environment variable.

## Folders

Bookmarks can be organised into folders and subfolders, but folders are **not**
directories on disk — every file lives flat in `bookmarks/`, and a bookmark's
folder is a `path` field inside it (e.g. `path: work/projects`, `""` = root).
The folder tree is reconstructed from those paths. Empty folders are recorded by
a small **folder object** (`type: folder`, with a `path`); a non-empty folder is
known from its bookmarks and needs no such object. The same URL may live in more
than one folder.

Keeping the folder inside the file (rather than in the directory layout) is what
lets an **encrypted** vault stay private on disk — the folder is inside the
ciphertext, so a public repo shows no collection names (see Encryption).

## Encryption

Any bookmark can be encrypted with a password. Encrypted bookmarks are stored as
opaque `<uuid>.yaml` files — **URL, title, and even the folder are all inside the
ciphertext**, so on disk an encrypted vault is just a pile of unreadable blobs
with no names or structure. That makes it safe to commit an encrypted vault to a
public git repo. They're also **invisible until you unlock with the password** —
the app won't even list them. See [docs/encryption.md](docs/encryption.md) for
the full design.

```bash
yaml-bookmarks add https://secret.example -e -p mypassword     # store encrypted (🔒)
yaml-bookmarks list                                            # encrypted ones are hidden
yaml-bookmarks list -p mypassword                              # unlock to see them (marked 🔒)
```

- Encryption uses AES-256-GCM with a key derived from your password via scrypt;
  the whole record is encrypted, a per-vault salt is embedded in each file, and
  each file is self-contained — copy any subset to another machine and unlock
  with the same password.
- In the web UI, a **padlock** in the header toggles it: click to enter a
  password (revealing encrypted bookmarks and encrypting new ones), click again
  to lock and hide them. Only one password is active at a time.

## Web UI

```bash
yaml-bookmarks web            # opens http://127.0.0.1:22222 in your browser
yaml-bookmarks web --port 9000 --no-browser
```

- Bound to `127.0.0.1` only, and requests with a non-local `Host` header are
  rejected (guards against DNS-rebinding).
- **Three-pane layout**: a collections sidebar on the left (folder tree with
  counts, collapsible, "New collection" button), the bookmark list in the
  centre, and the add/edit form on the right. On narrow screens it collapses to
  a single column with the form on top. Editing a bookmark and changing its
  collection moves it; the ⬇ Fetch button fills in title/description/keywords
  from the page.
- **Installable as a PWA**: because `http://localhost` is a secure context, your
  browser will offer to install it. It ships a web manifest, a service worker
  (so the shell launches offline), and app icons — all generated by the server,
  no binary assets in the repo.

## A stored bookmark

Each bookmark is a flat `<uuid>.yaml` file:

```yaml
url: https://example.com
title: Example
description: A description
tags:
- web
- reference
path: work/ideas      # the folder ("" = root)
created: 1769380888   # optional unix timestamp (seconds since the epoch)
```

An empty folder is recorded by a folder object instead:

```yaml
type: folder
path: work/ideas
```

`created` is optional — older bookmarks may not have it. Encrypted objects hold a
`crypt: true` blob whose decrypted payload is one of the above.

## Import

Import a **Raindrop.io CSV export** — its nested `Collection / Sub` folders become
`Collection/Sub`, `Unsorted` becomes the root, and tags/notes/dates carry over.

- **Web UI**: click **⬆ Import CSV** in the collections sidebar and pick the file.
- **CLI**: `yaml-bookmarks import export.csv` (add `-e -p PASSWORD` to import
  encrypted).

If a password is engaged (or `allow_unencrypted` is false and you've unlocked),
imported bookmarks are stored **encrypted**. Re-importing the same file is
idempotent (it upserts rather than duplicating).

## Settings

Global settings live in `~/.yaml-bookmarks/settings.yaml`, created with
documented defaults on first run:

```yaml
port: 22222               # port the web UI listens on
allow_unencrypted: false  # default: every new bookmark must be encrypted
```

- `port` — the web UI port; `yaml-bookmarks web --port N` overrides it.
- `allow_unencrypted` — **defaults to `false`**, so a fresh install requires
  encryption: adding an unencrypted bookmark is rejected (in the web UI you'll be
  prompted to unlock the padlock first). Set it to `true` to allow plaintext
  bookmarks.

Edit the file and restart the web server for changes to take effect.
